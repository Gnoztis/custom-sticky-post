# Custom Sticky Post

Один закреплённый пост в начале главной страницы блога. Закрепление включает
только администратор сайта; закреплённый пост получает собственное оформление,
а его миниатюра на главной скрывается — остальное содержимое ленты не меняется.

Версия 3.5.3. Требуется WordPress 7.0+ (проверено до 7.1) и PHP 8.4+.

## Возможности

- Метабокс «Закреплённый пост» в редакторе записи: флажок «Закрепить этот
  пост». Метабокс видят и используют только администраторы (право
  `manage_options`).
- Закрепить можно ровно один пост: если отметить другой, закрепление
  переносится на него, предыдущий пост становится обычным.
- На главной странице блога закреплённый пост выводится первым — только на
  первой странице; на страницах пагинации он не повторяется.
- Миниатюра закреплённого поста на главной не выводится.
- Пост получает CSS-класс `custom-sticky-post`; на главной к нему применяется
  тёмная карточка с акцентной полосой слева.
- Закрепление не связано со штатной «липкостью» WordPress (`sticky_posts`):
  это отдельный механизм, и его можно использовать вместе с ней.

## Установка

1. Скопировать каталог `custom-sticky-post` в `wp-content/plugins/`.
2. Активировать плагин в разделе «Плагины».
3. Открыть запись, в правой колонке включить флажок «Закрепить этот пост» и
   обновить запись.

## Как закрепить и снять закрепление

- **Закрепить** — отметить флажок у записи и обновить её. Если в этот момент
  закреплена другая запись, закрепление переходит к текущей.
- **Снять** — снять флажок у закреплённой записи и обновить её.
- Закрепление снимается автоматически, если закреплённый пост удалён или
  перестал быть опубликованным (черновик, корзина).
- Быстрая правка и сохранение через REST закрепление не меняют: флажок есть
  только в метабоксе записи.

## Оформление

На главной странице закреплённый пост помечается классом
`custom-sticky-post`, а в `<head>` добавляются стили для:

- `body.home .custom-sticky-post` — карточка (фон, полоса слева, отступы,
  тень);
- `body.home .custom-sticky-post .post-card__title`,
  `.post-card__content`, `.post-meta` — цвета текста внутри карточки.

Стили рассчитаны на разметку карточек темы (`post-cards`, `post-card__title`,
`post-card__content`, `post-meta`). Если тема использует другие классы,
оформление можно переопределить в дочерней теме по классу
`custom-sticky-post`.

## Какие данные хранятся

- Опция `custom_sticky_post_id` — ID закреплённой записи (одно число). Опция
  перезаписывается при переносе закрепления и удаляется, когда пост снят с
  публикации или удалён.
- Транзиенты `csp_github_release` и `csp_github_release_error` — кэш проверки
  обновлений (успешная проверка на 6 часов, ошибка на 15 минут).

## Обновления

Плагин обновляется штатным механизмом WordPress из репозитория
[Gnoztis/custom-sticky-post](https://github.com/Gnoztis/custom-sticky-post).
Берётся максимальная версия из GitHub Release и тегов (`vX.Y.Z` и `X.Y.Z`
равнозначны); предрелизы (`-beta`) и четырёхчастные версии (`X.Y.Z.N`) не
принимаются, поэтому достаточно поставить тег. Архив — zip-ассет релиза или
zipball победившего источника; принимаются только `https` и домены GitHub.

Проверка кэшируется на 6 часов. Если GitHub ответил ошибкой (например, 403 —
исчерпан лимит API), это видно в строке плагина и в уведомлении на странице
«Плагины»: показываются код и причина, а повторная автоматическая проверка
откладывается на 15 минут. Кнопка «Проверить обновления» сбрасывает кэш и
делает запрос сразу, не дожидаясь этой паузы.

### Токен GitHub (необязательно)

Без токена GitHub разрешает 60 запросов в час на IP-адрес сайта; одному
плагину этого хватает, но несколько плагинов на одном хостинге делят лимит и
могут получить 403. С токеном лимит — 5000 запросов в час.

Подойдёт fine-grained personal access token с доступом только к репозиторию
`Gnoztis/custom-sticky-post` и правом **Contents: Read** (для приватного
репозитория это обязательно; для публичного токен тоже поднимает лимит).
Токен задаётся в `wp-config.php`:

```php
define( 'CSP_GITHUB_TOKEN', '…' );
```

или фильтром:

```php
add_filter( 'csp_github_token', function () { return '…'; } );
```

Токен отправляется только на хосты GitHub (`api.github.com`,
`codeload.github.com`, `objects.githubusercontent.com` и скачивание релиза с
`github.com`) и только для файлов этого репозитория — чужие загрузки он не
увидит. Без токена всё работает как раньше, но с лимитом 60 запросов в час.

## Удаление

При удалении плагина `uninstall.php` удаляет опцию `custom_sticky_post_id` и
транзиенты проверки обновлений — на всех сайтах сети, без затрагивания данных
других плагинов.
